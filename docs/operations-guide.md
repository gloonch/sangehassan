# راهنمای عملیات پنل سنگ حسن

این راهنما برای مدیر غیرتکنیکال است. دسترسی هر بخش براساس نقش کاربر تعیین می‌شود؛ نبودن یک منو الزاماً خطا نیست.

## شروع روز کاری

1. در `/panel/` با شماره موبایل وارد شوید.
2. ابتدا «کارهای من» و سپس «موارد مهم» را بررسی کنید.
3. اعلان‌ها و موارد overdue را باز کنید و از لینک امن همان رکورد وارد جزئیات شوید.
4. برای یافتن سفارش، مشتری، پیش‌فاکتور، محموله، Batch یا پرداخت از جست‌وجوی Header استفاده کنید.

## کاربران و امنیت

- رمز موقت را فقط یک‌بار به صاحب حساب تحویل دهید. کاربر در اولین ورود باید آن را تغییر دهد.
- غیرفعال‌سازی، reset رمز و «ابطال نشست‌ها» کاربر را از Sessionهای قبلی خارج می‌کند.
- Role و Permission را با حداقل دسترسی لازم تخصیص دهید. آخرین Super Admin را حذف یا غیرفعال نکنید.
- کد فعال‌سازی مشتری محرمانه، هفت‌روزه و تک‌مصرف است. پس از سه تلاش ناموفق باید کد تازه صادر شود.

## تنظیمات و Moduleها

در `/panel/dashboard/settings` فقط Settingهای ثبت‌شده قابل ویرایش‌اند. خاموش‌کردن Inventory، Supplier یا Installation ایجاد عملیات جدید را متوقف می‌کند، ولی سوابق قبلی قابل مشاهده می‌مانند. خاموش‌کردن Portal فقط بخش عملیاتی حساب مشتری را می‌بندد و Login عمومی بازار را قطع نمی‌کند. تغییر Setting باید همراه دلیل ثبت شود.

## ابزارهای اصلاح

در `/panel/dashboard/admin-tools` ابتدا Diagnostics را اجرا کنید. Repair فقط برای عملیات شناخته‌شده‌ای مانند ساخت Action گم‌شده، بازسازی Actionها، اصلاح ETA، بازحساب Progress یا تطبیق Payment مجاز است. قبل از اجرا:

1. شناسه رکورد را با صفحه اصلی آن تطبیق دهید.
2. دلیل دقیق و قابل پیگیری بنویسید.
3. نتیجه را پس از موفقیت در Audit بررسی کنید.
4. Repair را با Refresh یا double-click تکرار نکنید؛ Idempotency از تکرار جلوگیری می‌کند.

این صفحه SQL یا ویرایش آزاد فیلد ندارد. برای ناسازگاری ناشناخته، رکورد را تغییر ندهید و موضوع را به تیم فنی ارجاع دهید.

## فایل‌ها و اطلاعات حساس

فایل‌های Workflow، پرداخت، QC، Shipment و Installation خصوصی‌اند. فقط از دکمه Download داخل پنل یا حساب مشتری استفاده کنید و لینک را عمومی نکنید. Customer فقط فایل customer-visible متعلق به سفارش خودش را می‌بیند. Cost، Profit، اطلاعات Lot، Supplier note، Audit و داده خصوصی QC نباید برای مشتری ارسال شوند.

## Audit و Export

Audit را بر اساس Actor، Action، Entity، Order و تاریخ فیلتر کنید. Before/After خلاصه است و Raw JSON فقط برای بررسی پیشرفته باز شود. Export حداکثر ۱۰هزار ردیف دارد و فیلتر Permission روی آن اعمال می‌شود. CSV حاوی PII یا اطلاعات مالی را فقط در فضای سازمانی نگهداری کنید.

## خطاهای رایج

- `MODULE_DISABLED`: Module توسط مدیر خاموش شده؛ سوابق قبلی همچنان قابل مشاهده‌اند.
- `INVALID_TRANSITION`: وضعیت رکورد در فاصله میان نمایش صفحه و Submit عوض شده؛ صفحه را Refresh کنید.
- خطای Idempotency با HTTP 409: همان کلید با payload متفاوت استفاده شده؛ وضعیت فعلی را بررسی و عملیات تازه را با کلید جدید انجام دهید.
- `PAYMENT_REQUIRED` یا `DOCUMENT_REQUIRED`: blocker نمایش‌داده‌شده را تکمیل کنید.
- Access Denied: نقش کاربر Permission لازم ندارد؛ به‌جای اشتراک حساب، دسترسی او را بازبینی کنید.

## Backup و بحران

Backup روزانه شامل Database و private files است: ۱۴ روزانه، ۸ هفتگی و ۱۲ ماهانه. Restore ماهانه باید در محیط ایزوله آزمایش شود. در قطعی یا خطای گسترده mutationها را متوقف، زمان و Request ID خطاها را ثبت و طبق checklist rollback عمل کنید؛ داده را با SQL دستی اصلاح نکنید.
